# Embedding baselines on bluefin (S4.2)

Benchmarks for roadmap step **S4.2** (competitor baselines) from
`docs/design/s4-embeddings-decisions.md` §4. They measure what Peregrine's
`/v1/embeddings` endpoint (PR #158, S4.1) will have to beat, and they build the
harness it plugs into (`benchmarks/embed.py`, `benchmarks/embed_report.py`).

> **Status: in progress.** Round 1 of `all-MiniLM-L6-v2` is complete; the other
> models are still being measured. Tables below are regenerated by
> `benchmarks/embed_report.py` from the raw JSON in this directory.

## Machine

| | |
|---|---|
| Host | bluefin, bare metal |
| CPU | AMD Ryzen 3 PRO 4350G (Zen 2), 4 cores / 8 threads |
| SIMD | AVX2 + FMA only (no AVX-512) |
| Memory | 13.5 GB, 8 GB swap (swap nearly full from earlier work on the host) |
| Kernel | 7.2.7-200.fc44.x86_64 |
| Governor | `powersave` (scales to 4.1 GHz under load; `scaling_cur_freq` 4.09 GHz max 4.11 GHz) |
| Threads | 4 (one per physical core) for every engine |
| Python | 3.14.8 |

Every timed invocation asserts `load average (1 min) < 0.5` and
`MemAvailable >= 5 GB`, and records both before and after each row
(`host_before` / `host_after` in the raw JSON). One engine and one model were
loaded at a time; every server was stopped before the next row started.

## Method

Grid: token lengths **16, 128, 512** × batch sizes **1, 8, 32, 128** texts per
request, **1 client**, plus **10 concurrent clients at batch 1**, 3 interleaved
rounds (round 1 over every row, then round 2, then round 3).

- Texts are built once per model from `benchmarks/prompts/corpus.txt` and
  calibrated with that model's own tokenizer to the target token count
  (16/128 exact, 512 in 508–512); every engine receives byte-identical texts.
  128 distinct texts per length. At L16 one text of 128 is 17 tokens for the
  Qwen3 and Gemma tokenizers (6% over; no 16-token window exists there).
- `texts/s` and `tokens/s` are wall-clock over the whole cell, tokens from the
  engine's own `usage` when it reports one, otherwise the tokenizer count
  (`tokens_source` in the JSON).
- p50/p99 are whole-request latencies.
- Cells that would need more than the per-row time cap are skipped and the
  reason is recorded in `<row>-skips.json` rather than being measured badly.
- Accuracy: mean cosine similarity of each (engine, model, precision) row to
  the fp32 PyTorch sentence-transformers vectors on 200 mixed-length texts
  (5 lengths × 40 texts, independent of the benchmark texts). Vectors are
  L2-normalised by every engine (recorded `norm` ≈ 1.0).
