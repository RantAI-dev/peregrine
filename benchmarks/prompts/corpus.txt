# Peregrine Benchmark Prompt Corpus

The Peregrine inference engine is designed for high-performance CPU execution of quantized large language models. The architecture centers around memory-bandwidth saturation during token decoding and compute saturation during prompt prefill and batched execution. Modern CPUs possess sophisticated memory hierarchies with multiple levels of cache, including high-speed L1 data caches, larger unified or per-core L2 caches, and massive shared L3 caches spanning tens or hundreds of megabytes. However, model parameter sizes for practical language models typically exceed several gigabytes, far outstripping the cache capacities of contemporary processors. Consequently, single-user autoregressive decoding is inherently bound by the bandwidth of the main memory interface.

In each autoregressive generation step, the model must read all weight matrices corresponding to the active layers from memory into the processor registers to perform matrix-vector multiplication against the hidden state vector. For a model with several billion parameters stored in quantized formats such as Q4_K_M, Q8_0, or ternary representations like PQ2_0, every token generated demands moving megabytes or gigabytes across the memory bus. If a machine sustains forty gigabytes per second of memory bandwidth and the active weights occupy two gigabytes, the absolute theoretical upper bound on generation speed is twenty tokens per second, regardless of compute capabilities.

To reach and sustain this memory ceiling, an inference engine must eliminate all extraneous memory traffic, optimize memory access patterns for CPU streaming hardware, minimize synchronization overhead among worker threads, and ensure instruction sequences achieve optimal retirement rates without pipeline stalls. When serving multiple concurrent users, the computational characteristics shift. By batching concurrent requests together, the engine can amortize the cost of reading weights across multiple user tokens, transforming memory-bound matrix-vector products into compute-intensive matrix-matrix multiplications. Under batched conditions, throughput scales toward the processor's fused multiply-accumulate peak, bounded by vector unit widths and core counts.

Benchmarking language model engines requires rigorous methodology. A single measurement taken in isolation is susceptible to operating system background tasks, dynamic frequency scaling fluctuations, thermal throttling, and memory subsystem contention. Accurate performance characterization demands repeated, interleaved executions across reference and competing engines under identical hardware and software conditions. Reporting medians alongside statistical spreads ensures that transient noise is identified and discounted, while comparing achieved performance against theoretical and measured hardware ceilings provides an objective metric of architectural efficiency.
